# 新闻推荐系统（MIND-small）

基于 MIND-small 构建的两阶段新闻推荐系统，覆盖数据管线、特征工程、
召回与排序模型、离线评估与服务化部署。

## 实验结果

评估协议：MIND-small dev 按时间顺序 70/30 切分，训练段统计特征，测试段评估。
所有模型使用完全相同的切分与候选集。

| 阶段 | 模型 | AUC | GAUC |
|---|---|---|---|
| 0 | 热度基线 | 0.6847 | 0.685 |
| 1 | GBDT（5 特征） | 0.7538 | 0.694 |
| 2 | GBDT（9 特征） | 0.7679 | 0.7108 |
| 3 | 双塔（平均池化） | 0.7149 | 0.689 |
| 4 | DIN（注意力池化） | 0.7554 | 0.7076 |
| 5 | **GBDT + 塔向量** | **0.7692** | **0.7165** |
| 6 | GBDT + 塔向量 + DIN | 0.7489 | 0.7068 |

服务化：Flask 单进程，19,114 用户可查，QPS 681 / P50 21.5ms / P99 65.2ms。

## 关键发现

1. **跨时间复用热度特征会失效**
   用 train（11/9–11/11）统计热度、在 dev（11/12–11/15）评估，AUC 仅 0.5039。
   改用同期数据 70/30 切分后回到 0.6847，验证了新闻场景下时间切分的必要性。

2. **全局 AUC 会被用户级特征虚高**
   GBDT 全局 AUC 0.7538，但 GAUC 只有 0.694。差值来自 `hist_len` 这类
   用户级特征——它只区分"该用户是否爱点击"，不区分"该推哪一条"。

3. **in-sample 堆叠会反噬**
   把 DIN 在训练集上的预测分数作为特征回灌 GBDT，GAUC 反而从 0.7165 跌至 0.7068。
   原因是该分数在训练集上"背过答案"，GBDT 过度依赖后无法迁移到测试集。
   正确做法是 K 折 OOF 预测。

4. **注意力优于平均池化**
   双塔与 DIN 使用相同的物品向量与训练数据，仅池化方式不同：
   GAUC 0.689 → 0.7076，提升 1.9 个点。
